# Функціонал управління ролями та паролями співробітників

## Огляд

Цей документ описує новий функціонал управління співробітниками з можливістю призначення ролей та індивідуальних паролів.

## Основні можливості

### 1. Створення співробітника з роллю та паролем

**Для адміністраторів:**

1. Натисніть кнопку ⚙️ біля поля "ФИО"
2. У модальному вікні заповніть форму:
   - **ФИО** (обов'язково) - ім'я співробітника
   - **Телефон** (необов'язково) - контактний номер
   - **Роль** (обов'язково) - виберіть USER або ADMIN
3. Натисніть "Добавить"
4. Система автоматично згенерує унікальний пароль та покаже його у спливаючому вікні

**Приклад згенерованого пароля:** `aB3!xY9z`

### 2. Управління існуючими співробітниками

У списку співробітників (модальне вікно) доступні такі дії:

- **✏️ Редагувати** - змінити ПІБ та роль
- **🔑 Змінити пароль** - встановити новий пароль
- **🗑️ Видалити** - видалити співробітника
- **Админ (чекбокс)** - швидка зміна ролі

### 3. Ролі користувачів

- **USER (👤)** - звичайний користувач, може брати/повертати ключі
- **ADMIN (👑)** - адміністратор, має повний доступ до управління співробітниками

## Технічні деталі

### Безпека паролів

- Паролі зберігаються у хешованому вигляді (bcrypt)
- Кожен співробітник має унікальний пароль
- При створенні генерується випадковий пароль (8 символів)
- Пароль показується тільки один раз при створенні

### Генерація паролів

Пароль містить:
- Великі літери (A-Z)
- Малі літери (a-z)
- Цифри (0-9)
- Спеціальні символи (!@#$%^&*)

### API endpoints

- `POST /api/people/add` - створення співробітника
- `POST /api/people/update` - оновлення даних
- `POST /api/people/delete` - видалення
- `POST /api/change-password` - зміна пароля

## Приклад використання

### Створення нового співробітника

```javascript
// Адміністратор створює співробітника через інтерфейс
// Система генерує пароль наприклад: "K7m#pL2q"
// Адміністратор повинен передати цей пароль співробітнику
```

### Вхід в систему

1. Співробітник вводить своє ПІБ (як логін)
2. Вводить отриманий пароль
3. Система перевіряє хеш пароля
4. При успіху - видається JWT токен

## Важливі зауваження

1. **Зберігайте паролі!** Після створення співробітника пароль показується лише один раз
2. **Мінімальна довжина пароля** при зміні - 4 символи
3. **Тільки адміністратори** можуть створювати/редагувати співробітників
4. **Не можна видалити останнього адміністратора** (потрібно хоча б одного)

## Відновлення доступу

Якщо співробітник забув пароль, адміністратор може:
1. Відкрити список співробітників
2. Натиснути 🔑 біля потрібного співробітника
3. Ввести новий пароль
4. Повідомити новий пароль співробітнику

## Рекомендації

1. Зберігайте згенеровані паролі у надійному місці
2. Надавайте паролі співробітникам через безпечні канали зв'язку
3. Регулярно змінюйте паролі (рекомендується кожні 90 днів)
4. Використовуйте складні паролі при ручній зміні

## Підтримка

За питаннями звертайтеся до адміністратора системи.
